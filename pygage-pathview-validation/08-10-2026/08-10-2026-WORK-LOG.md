## Confirmed bugs or compatibility problems

These items were reproduced with controlled tests. I listed them factually so
I could keep track of what needs another check first.

### PyGAGE

1. `pathway_gene_colors()` calls `matplotlib.cm.get_cmap`, which is unavailable in Matplotlib 3.11.1. The other tested new enrichment charts work.
2. `pygage.__all__` includes `normalize_gene_sets`, but the package does not import it at top level. `from pygage import *` therefore fails.
3. The paired-preparation documentation allows the sample count to be a multiple of the reference count, but a 4-sample/2-reference controlled case raises a NumPy shape error.
4. The permutation code shuffles complete prepared-data columns. The tested statistic is unchanged by column order, so the controlled permutation p-values were all `1.0`.

### Python Pathview Plus

1. The installed distribution reports version `2.0.2`, while `pathview.__version__` reports `2.0.0`.
2. `max_abs` and `random` aggregation use a Polars group UDF in a way that receives scalar values and raises an attribute error. Sum, mean, median, and max passed.
3. A normal namespaced SBGN-ML file parsed as zero glyphs and zero arcs because the glyph/arc searches are not namespace-qualified.
4. Catmull–Rom spline output contains `NaN` values for the documented example because duplicated endpoint points cause zero denominators.
5. The Python graph/PDF renderer uses only the first state. Native PNG and SVG correctly preserve two or three states.
6. The SVG and graph renderers create nodes but do not receive the parsed pathway relations, so pathway edges are not drawn.
7. `pathview()` returns a dictionary, while the composable highlighting example expects a `PathwayResult`. The two interfaces do not currently connect directly.
8. The documented discrete color option is accepted but not used by `node_color`.
